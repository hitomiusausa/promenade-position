## 目的

教本の各フィガーに記載された「先行フィガー」「後続フィガー」をデータ化する。
第一の消費者は将来のアマルガメーション自作ビルダー（第四弾 (a)）——「今のフィガーの次に来られるフィガー」を提案するため。
第二の消費者はフィガー詳細画面——「このフィガーの前後に踊れるもの」を表示するため。

## データの根拠（規律 D-15）

- 転記元は教本『ワルツ』の**各フィガー表の直下にある「先行・後続・註」の記述**のみ（利用者確認済み 2026-08-17）。受領済みの `docs/資料/pp_ワルツ.pdf` に含まれるため、新規資料の受領は不要。
- **教本にない繋がりは書かない。推測で補完しない。** 教本に条件付きで書かれているものは条件ごと転記する。
- 転記は利用者から教本該当箇所の提供を受けてから行う。照合は DATA_CHECK と同じ方式（生成シートで独立検収）。

## スキーマ（案A: 別ファイル `transitions.json` — 推奨）

```jsonc
// src/data/transitions.json
{
  "waltz": [
    {
      "from": "natural_turn",        // figures の id
      "to": "natural_spin_turn",     // figures の id
      "condition": null,             // 条件コード（下記）。無条件なら null
      "note_ja": null,               // 教本の註の転記（コード化できない場合のみ）
      "note_en": null,
      "source": "natural_turn/p.23"  // 記載元フィガー（表の下の記述の持ち主）＋ページ（検収用）
    }
  ]
}
```

- 教本が「Xの後続: Y, Z」と書く場合 → `{from: X, to: Y}`, `{from: X, to: Z}` の2エントリ。
- 教本が「Xの先行: W」と書く場合 → `{from: W, to: X}` に正規化（**保存は常に from→to の一方向**。Wの後続欄とXの先行欄に同じ繋がりが載る場合は1エントリにまとめ、`source` に両方の記載元を `;` 区切りで併記——教本内部の相互参照の整合もこれで検収できる）。

### 案B（不採用候補）: figures 側に `precede`/`follow` 配列を持たせる

却下理由: 同じ繋がりが2箇所に書かれ整合性検証が必要になる。条件・註の置き場も歩データと混ざる。transitions を独立させれば図（フィガー遷移グラフ）の導出も素直。

## 条件コード

教本の条件表現は D-04 の規約どおり `types.ts` の列挙＋ja/en 両辞書をセットで追加する。

```ts
// types.ts（追加分の例。実際の値は教本の表現を見てから確定する）
export type TransitionCondition =
  | "ending_in_PP"        // 「PPで終わる場合」
  | "ending_facing_DW"    // 例。教本の実表現に合わせて命名
  ;
```

- 列挙で表せない自由記述の註だけ `note_ja`/`note_en` に転記（原文まま。翻訳は en 側のみ）。
- 条件コードの命名は既存コード（`continue_rise_lower_eo_3` 等）の流儀に合わせる。

## 検証（`npm run validate-data` に追加）

1. `from`/`to` が figures の id に存在すること（stub 含む）。
2. 重複エントリ（from, to, condition が同一）の禁止。
3. `condition` が列挙に存在すること。
4. `source` 必須（検収可能性の担保）。
5. stub エントリは歩データを持たないこと／transitions のどこにも現れない stub の禁止（不要な骨の混入防止）。

### 未収録フィガー（インピタス等、残り28）への言及

教本は収録済み39以外のフィガーを先行・後続に挙げるはず。選択肢:

- **採用（2026-08-17 利用者承認）**: `to`/`from` に未収録フィガーの id を許す。figures 側に `stub: true` の骨だけエントリ（id・名前・辞書のみ、歩データなし。名前は教本の目次／表題から転記）を作る。フィガー一覧は stub を除外。ビルダー／詳細画面は stub を「未収録」とグレー表示・リンクなし。将来フィガーを追加したとき stub を実体に置き換えるだけで transitions が生きる。
- 代替（不採用）: (案2) 未収録への言及は転記しない → 照合が「一部転記」になり検収が濁る。将来の拾い直しの二度手間。 (案3) figures はいじらず validate に未収録 id の許可リストを持たせる → 名前辞書が結局必要で手間が stub と同等なのに検証が緩む。許可リストとフィガー追加の同期漏れが温床。
